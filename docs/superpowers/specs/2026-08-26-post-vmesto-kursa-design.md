# Пост вместо курса с уроками

**Дата:** 2026-08-26
**Статус:** утверждено заказчиком

## Задача

Убрать двухуровневую структуру «курс → уроки». Единица контента — один пост:
одна страница, один экран, одна запись в базе. Неважно, что внутри — промт,
обучающий разбор или заметка. Читатель находит пост в каталоге, открывает и
читает целиком, без переходов «урок 7 из 13».

Внутри поста всё, что предназначено для копирования — код, команды командной
строки, промты — копируется одним нажатием и видно с первого взгляда.

## Модель данных

Таблицы `courses` и `lessons` и представление `course_with_stats` удаляются.
Взамен одна таблица `posts`:

| поле | тип | смысл |
|---|---|---|
| `id` | uuid | |
| `slug` | text unique | часть адреса `/p/<slug>` |
| `title` | text | |
| `subtitle` | text | одна строка под названием на карточке |
| `category_id` | text → categories | направление |
| `cover` | jsonb | градиент + необязательная картинка |
| `badges` | text[] | `new`, `free` |
| `blocks` | jsonb | тело поста |
| `read_min` | integer | время чтения, считается автоматически |
| `published` | boolean | черновик виден только админу |
| `sort_order` | integer | |

Уходят `level`, `author`, `description`, `lessons_count`, `duration_min`.
Уровень бессмыслен для промта, автор всегда один, описание дублировало
подзаголовок и первый абзац.

`read_min` хранится, а не считается на лету: карточки каталога показывают
время, и тянуть `blocks` всех постов ради одного числа — лишние сотни
килобайт на каждом открытии. Значение пересчитывается функцией
`estimateReadMin(blocks)` при каждом сохранении в админке — это единственное
место записи, поэтому разъехаться значению негде.

### Типы

```ts
type PostBlock =
  | { type: 'heading'; text: string }
  | { type: 'text'; text: string }
  | { type: 'image'; cover: PostCover; caption?: string }
  | { type: 'list'; ordered?: boolean; items: string[] }
  | { type: 'quote'; text: string; author?: string }
  | { type: 'callout'; tone: 'info' | 'warning' | 'success'; text: string }
  | { type: 'code'; lang: string; code: string }
  | { type: 'command'; command: string; note?: string }
  | { type: 'prompt'; text: string; title?: string }

interface Post { id, slug, title, subtitle, categoryId, cover, badges, readMin }
interface PostDetail extends Post { blocks: PostBlock[] }
```

`Post` — то, что нужно карточке в списке. `PostDetail` приезжает только при
открытии поста. Порт каталога сокращается до пяти методов: `getCategories`,
`getPosts(categoryId?)`, `searchPosts`, `getPostsByIds`, `getPost(slug)`.

## Экран поста

Адрес `/p/:slug`, экран `src/screens/post/PostScreen.tsx`.

Сверху вниз: обложка 240px с кнопкой «назад» (вне Telegram) и закладкой,
бейджи в нижнем углу обложки; заголовок с иконкой направления; подзаголовок;
строка `направление · N мин`; тело поста; кнопка «к каталогу» в конце.

Ничего из прежнего экрана курса не остаётся: ни списка уроков, ни прогресс-бара,
ни «начать курс», ни главной кнопки Telegram.

## Копируемые блоки

Общий хук `useCopy(text)`: `navigator.clipboard.writeText` с запасным вариантом
через скрытое `textarea` (внутри Telegram WebView clipboard API доступен не
всегда), тактильный отклик и состояние `copied` на 1.6 секунды. Общая кнопка
`CopyButton` переключает иконку на галочку.

- **`code`** — рамка, шапка: язык слева, кнопка копирования справа. Тело
  прокручивается по горизонтали внутри своего контейнера, страница при этом
  не едет.
- **`command`** — тёмная плашка, красный `$`, команда с переносом по словам:
  длинную команду надо видеть целиком, а не искать в скролле. Кнопка справа,
  под плашкой необязательная подпись, что команда делает.
- **`prompt`** — карточка с надписью «промт», необязательным заголовком,
  текстом и кнопкой «скопировать промт» во всю ширину плюс счётчик символов.
  Шрифт в интерфейсе один на всё (JetBrains Mono), поэтому от кода промт
  отличается вёрсткой, а не гарнитурой: межстрочный интервал прозы, перенос
  по словам, рамка.

Высота любой кнопки копирования не меньше 36px: это телефон и палец.

## Личное состояние

`library.store` версии 3. Остаются `saved: string[]` и
`lastOpened: { postId, at } | null`. Удаляются `completed`, `markLessonDone`,
`markLessonUndone`, `resetCourse`, `progressOf` и все селекторы прогресса.
Прежнее содержимое хранилища не мигрируется: идентификаторы сменились вместе с
таблицей.

Секция «Продолжить» на Главной становится «недавно открытое» — одна карточка
без полоски прогресса. Из профиля уходит ряд статистики по урокам, а «сбросить
прогресс» превращается в «очистить закладки».

## Админка

Два экрана вместо трёх: список постов и `/admin/post/:id`.
`AdminLessonScreen` удаляется, редактор блоков переезжает в экран поста.

На экране поста содержание идёт **первым**, метаданные — ниже, в сворачиваемой
секции «настройки поста». Сейчас до тела приходится проматывать восемь полей;
редактируют же в основном текст. Сверху липкая шапка с названием, кнопкой
сохранения (показывает состояние) и ссылкой «открыть пост».

Добавление блока — сетка из девяти кнопок с иконками вместо выпадающего списка.

## Контент

Курс `remotion-video-kodom` (7 уроков, ~44 минуты) пересобирается в один пост
примерно на 11 минут: что это → зачем → композиция и `useCurrentFrame` →
`interpolate` и `spring` → звук и длина ролика → скиллы Claude Code → первый
ролик. Весь код в `code`-блоках, все `npx` и `edge-tts` — в `command`, задача
для Claude Code — в `prompt`. Переходные абзацы между уроками, повторы и
цитаты-афоризмы выбрасываются.

Моковый каталог (`src/data/courses.ts` + `src/data/lessons.ts`) превращается в
`src/data/posts.ts` одноразовым скриптом: блоки уроков склеиваются подряд,
название урока становится заголовком. Моки — резервный источник для работы без
Supabase, ручная переработка каждого из тринадцати не окупается.

## Миграция базы

`supabase/migrations/0002_posts.sql`:

1. создать `posts`;
2. перенести каждый курс со склеенными блоками его уроков;
3. удалить представление `course_with_stats`, таблицы `lessons` и `courses`;
4. перевесить политики RLS на `posts` (читают все опубликованные, правит админ).

Шаг необратим. Резервная копия контента остаётся в `supabase/seed-*.sql` в
репозитории.

## Отклонения при реализации

- Промт задумывался пропорциональным шрифтом — в проекте моноширинный шрифт
  один на весь интерфейс, различие сделано вёрсткой (см. выше).
- Моковый пост про Remotion в `src/data/posts.ts` и запись в базе — одно и то
  же содержание: сид генерируется из мока.

## Проверка

Тестового фреймворка в проекте нет. Верификация: `npm run build`,
`npm run lint`, открытый в браузере пост с проверкой копирования кода,
команды и промта, а также прохода по админке — создание, правка, публикация.

## Чем платим

- Прогресс чтения теряется у всех, кто уже что-то проходил. Данных мало,
  приложение не запущено публично.
- Длинный пост нельзя проходить по частям — по решению заказчика навигации
  по содержанию не будет, только сплошной текст.
- Возврат к многочастному формату потребует новой миграции.
