# 0006. Состояние — zustand, без глобального стора для каталога

**Дата:** 2026-08-24
**Статус:** принято

## Контекст
Нужно хранить пользовательское состояние (закладки, прогресс, настройки) и
серверное (курсы, уроки). Это разные по природе данные.

## Решение
- Пользовательское состояние — zustand-сторы `useLibraryStore`, `useSettingsStore`
  с persist в KeyValueStore из ADR 0003.
- Данные каталога в глобальный стор не кладём: экраны запрашивают их через хук
  `useAsync` у репозитория и держат локально.

## Почему
- Каталог только читается и никогда не правится из интерфейса — глобальное
  состояние для него было бы лишним слоем.
- zustand не требует провайдеров и boilerplate, а его persist легко подружить
  с асинхронным CloudStorage.
- Когда появится настоящий API, кэширование запросов решается заменой `useAsync`
  на TanStack Query без правки экранов.

## Чем платим
- Пока нет кэша между экранами: возврат на Главную заново дёрнет репозиторий.
  На моках это бесплатно, на HTTP потребует TanStack Query.

## Что рассматривали ещё
Redux Toolkit — слишком много церемоний для четырёх экранов.
Context + useReducer — пришлось бы вручную писать persist и селекторы.
