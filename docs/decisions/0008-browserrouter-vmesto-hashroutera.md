# 0008. BrowserRouter вместо HashRouter

**Дата:** 2026-08-24
**Статус:** принято
**Заменяет:** решение о HashRouter из 0001

## Контекст
В 0001 был выбран HashRouter — ради того, чтобы не настраивать rewrite
на хостинге. Решение не учло главного: Telegram передаёт мини-аппу свои
данные через фрагмент URL.

При запуске из бота Telegram открывает адрес вида
`https://приложение/#tgWebAppData=…&tgWebAppVersion=7.0&tgWebAppPlatform=android`.
HashRouter читает этот фрагмент как путь, маршрута `/tgWebAppData=…` не находит
и показывает страницу ошибки. В обычном браузере фрагмент пустой, поэтому
при проверке всё выглядело исправным — ошибка вылезла только в реальном боте.

## Решение
`createBrowserRouter`. Хеш остаётся Telegram, путь — приложению.
В `vercel.ts` добавлен rewrite: любой путь, кроме файлов с расширением
и папки `assets`, отдаёт `index.html`.

Заодно у корневого маршрута появился `errorElement`: раньше при любой ошибке
пользователь видел техническую страницу react-router с советами разработчику.

## Почему
- Это единственный способ не конфликтовать с Telegram: фрагмент занят им,
  и отобрать его нельзя.
- Rewrite на Vercel — одна строка конфигурации, а не отдельная инфраструктура.
- Адреса становятся человеческими: `/course/git-bez-straha` вместо
  `/#/course/git-bez-straha`.

## Чем платим
- Хостинг обязан уметь rewrite. Переезд на статику без такой возможности
  (например, простой файловый сервер) потребует вернуться к этому решению.
- Ранее выданные ссылки с `#/` перестали работать. Их никто не успел сохранить.

## Что рассматривали ещё
Чистить хеш вручную перед созданием роутера — то есть вырезать `tgWebApp*`
и оставлять остальное. Отпало: SDK Telegram читает фрагмент сам, и вмешиваться
в этот момент — значит зависеть от порядка загрузки скриптов.

## Урок
Проверка «в браузере работает» для мини-аппа Telegram ничего не доказывает.
Окружение отличается ровно тем, что задаёт поведение — и это надо
воспроизводить: открыть локальный адрес с поддельным
`#tgWebAppData=…&tgWebAppVersion=…` перед тем, как считать задачу сделанной.
