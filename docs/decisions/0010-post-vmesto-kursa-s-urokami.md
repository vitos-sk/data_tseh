# 0010. Пост вместо курса с уроками

**Дата:** 2026-08-26
**Статус:** принято

## Контекст
Каталог строился как «курс → уроки»: карточка курса, экран программы, экраны
уроков, прогресс по пройденным, переходы «урок 7 из 13». Заказчик наблюдал за
этим на живом контенте и сформулировал прямо: читателю нужен один пост, а не
маршрут по частям. Тематика значения не имеет — обучающий разбор, готовый
промт и короткая заметка должны жить в одной форме.

## Решение
Единица контента — пост. Одна таблица `posts` вместо `courses` + `lessons`,
один экран `/p/:slug` вместо экрана курса и экрана урока, один экран в админке
вместо трёх.

Прогресс чтения убран целиком: `completed`, полоски прогресса, «продолжить с
урока». Осталось личное состояние из двух вещей — закладки и последний
открытый пост.

## Почему
- Читать по частям нечего: пост закрывается за один заход.
- Прогресс по урокам — единственное, ради чего существовала вложенность.
  Без него уровень уроков не нёс смысла.
- Три экрана в админке заменились одним: правка текста перестала требовать
  прохода «список → курс → урок».
- Форма перестала обещать структуру, которой у половины материалов нет:
  промт — это не курс из семи уроков.

## Чем платим
- Прогресс потерян у всех, кто что-то проходил. Приложение не было запущено
  публично, данных мало.
- Очень длинный материал теперь одна страница. Навигацию по содержанию
  заказчик отклонил осознанно: только сплошной текст.
- Возврат к многочастному формату потребует новой миграции.

## Что рассматривали ещё
Оставить `courses` с полем `blocks` и одним уровнем: миграция вышла бы на
пятнадцать строк, но в коде навсегда остались бы `Course`, `courseId` и
`/course/:slug` при отсутствии курсов. Отвергнуто как заведомый мусор.
