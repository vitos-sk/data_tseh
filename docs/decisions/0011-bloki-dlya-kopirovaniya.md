# 0011. Отдельные типы блоков для кода, команды и промта

**Дата:** 2026-08-26
**Статус:** принято

## Контекст
Половина ценности постов — то, что читатель заберёт себе: команда установки,
кусок кода, промт для нейросети. В прежней модели всё это было одним типом
`code`: моноширинный блок без кнопки копирования. Скопировать команду
получалось только выделением пальцем по экрану телефона.

## Решение
Три отдельных типа блока вместо одного:

- `code` — язык в шапке, кнопка копирования справа, прокрутка внутри блока;
- `command` — знак `$` (в буфер не попадает), перенос по словам, кнопка справа,
  необязательная подпись «что делает»;
- `prompt` — рамка, необязательный заголовок, счётчик символов и кнопка
  «скопировать промт» во всю ширину.

Копирование — общий хук `useCopy` с запасным путём через скрытое `textarea`.

## Почему
- В буфер должно попадать разное: у команды — без `$`, у промта — весь текст
  вместе с переносами строк. Один тип блока это не различал.
- Команду перед запуском читают целиком, поэтому у неё перенос по словам, а не
  прокрутка: спрятанный хвост — прямой путь выполнить не то, что собирался.
- У промта копирование — главное действие, а не мелкая кнопка в углу.
- Clipboard API требует защищённого контекста и разрешения, а внутри WebView
  Telegram выполняется не всегда. Молча не скопировать — худшее, что может
  сделать кнопка, существующая ради копирования.

## Чем платим
- Три типа блока вместо одного: и в редакторе, и в рендере, и в объединении
  `PostBlock`.
- Автор поста должен выбрать правильный вид. Панель добавления подсвечивает
  копируемые блоки красным, но ошибиться всё ещё можно.

## Что рассматривали ещё
Оставить один `code` с флагами (`copyable`, `kind`). Отвергнуто: набор полей
у промта и команды разный, а флаги на объединении быстро превращаются в
проверки «если kind = prompt, то title обязателен» вместо типов.
