# Цех — Telegram Mini App

Платформа коротких постов: код, AI, бизнес, ремесло, лайфхаки. Один пост —
одна страница: разбор, инструкция или готовый промт, с командами и кодом,
которые копируются одним нажатием.
Приложение открывается внутри Telegram, но полностью работает и в обычном браузере.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
npm run lint
```

## Как это устроено

Зависимости идут строго в одну сторону:

```
экраны → модули (catalog, library, settings) → платформа (telegram, storage)
                    ↘ компоненты (ui, layout, post) ↗
```

| Папка | За что отвечает |
|---|---|
| `src/app` | Точка входа, роутер, палитра (`theme.css`, `colors.ts`) |
| `src/platform/telegram` | Обёртка над Telegram WebApp SDK: BackButton, MainButton, Haptics, вьюпорт |
| `src/platform/storage` | Асинхронное key-value: Telegram CloudStorage или localStorage |
| `src/modules/catalog` | Посты и категории. Единственная дверь к данным — `catalog.repository` |
| `src/modules/library` | Личное: закладки и последний открытый пост. Знает только идентификаторы |
| `src/modules/settings` | Настройки приложения |
| `src/data` | Моковый контент |
| `src/components` | UI-кит, layout, карточки постов, рендер блоков |
| `src/screens` | Пять экранов приложения |

Ключевое разделение: **library не знает содержимого постов**, только их `id`.
Сшивают их экраны — например, «Закладки» берёт список id из library
и запрашивает по нему посты у catalog.

## Поведение интерфейса

- Таб-бар виден на всех экранах, включая открытый пост (ADR 0007).
- На экране шире `md` приложение рисуется колонкой в 440px по центру —
  ширина задаётся переменной `--app-width`.
- Настройка «Меньше анимации» в профиле ставит `data-motion="reduced"`
  на `<html>`; системный `prefers-reduced-motion` учитывается тоже.
- Опасные действия подтверждаются прямо в строке. Нативный `confirm()`
  использовать нельзя — он блокирует WebView Telegram.

## Что где менять

- **Добавить пост** — через админку. Моковый каталог для работы без базы —
  `src/data/posts.ts`; время чтения там считается `estimateReadMin`, вручную
  его не проставляют.
- **Подключить настоящий API** — `src/modules/catalog/catalog.repository.ts`. Экраны не трогать.
- **Новый тип блока** (видео, тест) — вариант в `PostBlock`, ветка в
  `src/components/post/BlockRenderer.tsx` и ветка в редакторе
  `src/screens/admin/AdminBlockEditor.tsx` (ADR 0004, 0011).
- **Цвета** — `src/app/theme.css` (для CSS) и `src/app/colors.ts` (для JS).
- **Ширина колонки на ПК** — переменная `--app-width` в `src/app/theme.css`.

## База данных

Каталог живёт в Supabase (создан через Vercel Marketplace). Приложение
переключается на базу само, как только видит ключи `VITE_PUBLIC_SUPABASE_*`;
без них работает на данных из `src/data`.

```bash
vercel env pull                                    # забрать ключи в .env.local
npm run db:apply -- supabase/migrations/0001_init.sql   # схема и политики доступа
npm run db:apply -- supabase/migrations/0002_posts.sql  # курсы с уроками → посты
npm run seed:sql && npm run db:apply -- supabase/seed.sql  # данные из src/data
npm run db:admin -- почта@пример.ру                # выдать права редактора
npm run db:status                                  # что сейчас в базе
```

Права заданы в самой базе (RLS): читать опубликованное может кто угодно,
писать — только тот, чья строка есть в таблице `admins`. Интерфейс админки
эти права не выдаёт, он лишь показывает понятный экран вместо ошибок доступа.

## Админка

Адрес: `/studio`, меняется переменной `VITE_ADMIN_PATH`. Вход по паролю.
Два экрана: список постов и редактор. В редакторе содержание идёт первым,
метаданные — в сворачиваемой секции под ним; блоки добавляются панелью из
девяти видов, где копируемые (код, команда, промт) выделены красным.
Картинки грузятся в bucket `covers`.

Секретность адреса — не защита: путь виден в собранном коде. Дверь запирают
вход и политики базы.

## Деплой

Проект развёрнут на Vercel и пересобирается сам при пуше в `main`:
**https://data-tseh.vercel.app**

Настройки лежат в `vercel.ts`: фреймворк Vite, сборка `npm run build`,
вечный кэш для файлов из `assets` (их имена содержат хеш содержимого).
Заголовки, ограничивающие встраивание в iframe, намеренно не заданы —
Telegram Desktop открывает мини-апп именно в iframe.

## Публикация в Telegram

1. Взять адрес деплоя (или свой домен на HTTPS).
2. В [@BotFather](https://t.me/BotFather): `/newapp`, указать URL мини-аппа.
3. Хостинг обязан отдавать `index.html` на любой путь — на Vercel это
   настроено в `vercel.ts`. Приложение использует обычные адреса, потому что
   фрагмент URL занят самим Telegram (ADR 0008).

### Как проверить мини-апп, не открывая бота

Откройте локальный адрес с поддельными данными Telegram — именно так
выглядит запуск из бота, и именно на этом ловятся ошибки, невидимые
в обычном браузере:

```
http://localhost:5173/#tgWebAppData=user%3D%257B%2522id%2522%253A1%252C%2522first_name%2522%253A%2522Тест%2522%257D&tgWebAppVersion=7.0&tgWebAppPlatform=android
```

## Известные ограничения

- Закладки живут в Telegram CloudStorage, аналитики по ним нет — нужен бэкенд.
- Прогресса чтения нет и не планируется (ADR 0010).
- Навигации по содержанию внутри длинного поста нет — только сплошной текст.
- Обложки постов рисуются CSS-градиентами, если не загружена картинка.
- Мультиязычности нет, все тексты русские.
- В базе один написанный пост — «Видео через Claude Code». Моковый каталог
  содержит ещё тринадцать, из них восемь — только описание без содержания.
